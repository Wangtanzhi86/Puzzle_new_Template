# 序列帧播放时配「女人音效」

## 改了什么
- `assets/scripts/audio/AudioManager.ts`：`AudioCue` 新增 `startSlot`（Inspector「激活事件的槽位」，默认 -1）。`build()` 里 `ch.onStart` 包一层：`startSlot >= 0` 时只有事件载荷第一个参数（槽位号）等于它才播。
- `assets/scene.scene`：Canvas 的 `AudioManager` 追加一条 cue —— 激活事件 `PIECE_REPAIRED`、`startSlot = 0`（= `Slot_02`：`BrokenLayer` 下只有 `Slot_02/03/04` 三格，按 `pieceId` 排序后它排第 0）、音效 `女人音效.MP3`（uuid `2c48d6d0-30b4-444d-9459-0e92ddce53f2`）、音量 1。
- 同一轮把 `Scene_BG` 上盯 `Slot_03` 的 `SlotSwap` 的 `delay` 改回 0（上一轮被编辑器存盘写成 0.2，`waitShown` 仍为 true）。
- `docs/TUNING.md` 音频那一行补上「激活事件的槽位」。

## 为什么这么改
- 场景里只有 `小三1动作`（#522）挂了 `SlotSequence`（#525，17 帧，watch `Slot_02`，delay 0），它在 `PIECE_REPAIRED` 当刻起播，所以音效跟同一个事件对齐即可。
- 没有在 `SlotSequence` 里直接加 `AudioClip` + `AudioSource`：那样绕开 `AudioManager`，平台静音（`AUDIO_MUTE`）、首次交互解锁、`END_SHOW` 停全部都会漏；也没有新增事件名（§5 不允许），只在监听侧加过滤。
- 否掉的方案：给 `SlotSequence` 加 `sound` 属性直接 `source.play()`（合规三条都要重写一遍）；用 `REPAIR_PROGRESS` 之类别的总线事件（时机不等于序列帧起播）。

## 怎么验的
- `node` 解析 `assets/scene.scene` 通过：`len 877`，新 cue 在 `#876`，`AudioManager.cues` 已含 `876`；`SlotSwap#507` 的 `delay = 0`、`waitShown = true`。
- 未跑 `verify-scene.js`（当时 MCP 端口 27502 无监听）。

## 影响什么 / 还没验的
- 其余 cue 的 `startSlot` 默认 -1，行为不变。
- 音效绑的是「槽位号 0」（= `Slot_02`）。以后序列帧改绑别的槽位，这条 cue 的「激活事件的槽位」要一起改。
- 还没在编辑器预览里听：需要在 `Slot_02` 修好那一下确认「小三动作」起播与女声同时。
