# 修复表现期间锁定拖动

- 日期：2026-10-22
- 提交：未提交
- 关联：AGENTS.md §5（事件驱动）/ §10（工作方式）

## 改了什么

- [GameEvent.ts](assets/scripts/core/GameEvent.ts)：新增 `DRAG_HOLD` / `DRAG_UNLOCK`，只服务于「拖动锁」。
- [DragController.ts](assets/scripts/gameplay/DragController.ts)：新增 `_effectHolds`，只监听 `DRAG_HOLD` / `DRAG_UNLOCK` 计数；`onStart` 在计数大于 0 时直接返回，不再拿起下一块。`LEVEL_BUILT` / `onDisable` 重置计数。
- [PieceSlot.ts](assets/scripts/level/PieceSlot.ts)：`repair()` 在原有 `GUIDE_HOLD` 旁多发一次 `DRAG_HOLD`；`finishShown()` 在原有 `GUIDE_RESUME` 旁多发一次 `DRAG_UNLOCK`，覆盖这一格从吸附到揭晓演完的整段。
- [BubbleSequence.ts](assets/scripts/ui/BubbleSequence.ts)：把 `DRAG_HOLD` 放在 `onShown` 里、延迟开始前，气泡 1 / 2 / 3 整段都按住；`_guideHeld` 改成可重入计数 `_guideHolds`，气泡 2 藏好、气泡 3 藏好各放行一次，`onDisable` / `LEVEL_BUILT` 兜底放行全部。原有 `GUIDE_HOLD` / `GUIDE_RESUME` 同步保留，空闲引导仍被按住。
- [SlotSequence.ts](assets/scripts/gameplay/SlotSequence.ts)：角色序列起播时 `holdGuide()`，最后一帧、`onDisable`、`LEVEL_BUILT` 时 `releaseGuide()`；`小三1动作` 与 `男女主动作` 都走同一条规则。
- 没有新增 Inspector 参数，也没有改场景 / 预制体；锁定窗口完全由各表现时长决定。

## 为什么这么改

- **问题**：吸附成功后，揭晓、气泡、角色序列还在演，玩家已经能从池子里拖走下一块，画面会叠在一起。
- **不复用 `GUIDE_HOLD` / `GUIDE_RESUME` 做拖动锁**：它首先是空闲引导的窗口信号，和 `GuideController` 共用。更关键的是 `GameEntry` 在选关时会发一次 `GUIDE_HOLD`，而本该配对收掉的 `GameIntro`（uuid `be3125e2-764f-41d1-9822-9825b51b7ac3`）并不在 `assets/scene.scene` 里；把同一个信号拿来做拖动计数，就会一进关永久锁死。新增一对独立事件，两个窗口互不牵连。
- **气泡在 `onShown` 就按住，而不是起播时**：触发后还有可配置的 `delay`，起播前的空窗期也不该让玩家把下一块拿走；气泡 2 / 3 的整段同理。
- **角色序列也按住**：`小三1动作` 17 帧约 2.2 秒、`男女主动作` 10 帧约 1.3 秒，都是「上一块修好后还在演」的表现；不锁的话玩家可以在角色动作中途拖下一块。
- **计数而不是布尔**：一格揭晓、气泡、角色序列可能重叠，各自 hold / release 一次，计数归零才真正放行。
- **没有给 `RepairSweep` / `SlotSwap` 单独加 hold**：本轮场景里 `sweepOnRepair` 是关的，槽位 2 / 3 / 4 的 `SlotSwap` 又分别落在气泡或角色序列的窗口内；先不为短过渡重复加锁，后续若把扫光打开且仍有空窗，再按同一模式补。

## 怎么验的

- `npm run check` 退出码 0，只有原有的 `ProgressController.label = null` 与背景九宫格 inset 未配两条提示。
- `node tools/exec.mjs editor tools/js/refresh.js` 后，在编辑器里跑临时探针（跑完已删）：
  - 发两次 `DRAG_HOLD` → `DragController._effectHolds = 2`，`onStart` 被拦下（`holding = false`、`_entry = null`）；
  - 发一次 `DRAG_UNLOCK` → 计数 `1`，再发一次 → `0`，此时 `onStart` 可以正常拿起；
  - `BubbleSequence` 连续两次 hold → `2`，release 一次 → `1`，全部 release → `0`；
  - 三个组件的新方法都已编译进运行时。
- 没有跑预览 / 截图，没有在真机上验证。

## 影响什么 / 还没验的部分

- 每次吸附成功后，池里的其他碎片在「这一格揭晓 + 气泡 + 角色序列」全部演完前都拿不起来；已经拿在手上的那一块不受影响。
- `onStart` 直接返回时，池子的 ScrollView 仍可能按自己的手势滚动；「锁定期间是否允许滚池子」没有单独处理，也没在触屏上验。
- 如果外部还有别的组件发 `DRAG_HOLD` 却没有配对 `DRAG_UNLOCK`，拖动会一直锁着；现有发射方（`PieceSlot` / `BubbleSequence` / `SlotSequence`）都已配对，`LEVEL_BUILT` / `onDisable` 还有兜底重置。
- 没有新增 Inspector 参数；改气泡打字速度 / 序列帧间隔会同步改变锁定长度。
- 未改场景，所以不需要重新存场景；但脚本刷新后要重开预览才会跑新逻辑。
