# 预填飞行放慢 + 引导等预填演完再出现

- 日期：2026-10-20
- 提交：<待回填>
- 关联：AGENTS.md §5 / §16 / docs/TUNING.md

## 改了什么

- `PrefillFlight.flyTime`：`0.55` → `1` 秒（代码默认值与场景序列化值一起改），碎片飞进缺口的过程明显放慢。
- `GuideController` 新增 `prefillDelay = 2`：有预填槽位的关卡，第一次引导要等该格 `PREFILL_DONE`
  （飞入 + 金色烟花 + 圆形扩散全部演完）之后再等 2 秒才出现。
- `GuideController.idleDelay`：`3.5` → `3` 秒（玩家碰屏收掉引导后，重新出现的时间）。
- 预填完成后的那 2 秒等待里，玩家碰屏幕**不会**把引导提前到 0.5 秒；等待结束后照常受 `idleDelay` 控制。
- `docs/TUNING.md` 引导那一行补 `prefillDelay`，并新增 `PrefillFlight` 的调参行。

## 为什么这么改

- **不能在 `GAME_START` 后固定等 2 秒**：预填的飞行 + 揭晓总时长会随 `flyTime` / 烟花 / 扩散参数变，
  固定值要么盖住揭晓、要么白等。改成等 `PREFILL_DONE` 再起算，才真的「预放置完成之后」。
- **不用 `GUIDE_RESUME` 实现**：那条恢复播的是 `idleDelay`（3 秒），预填后想要的是 2 秒，语义也不同。
- **等待期间忽略触摸**：这时引导还没出现过，玩家碰屏幕若按老逻辑走 `firstDelay`，就会在预填刚演完 0.5 秒后
  冒出来，违背「延迟 2S」。所以单独用 `_prefillWait` 标记这段窗口，触摸不打断。
- 否掉的方案：只把 `firstDelay` 调成 2 —— 无法保证在预填演完之后起算；在 `PrefillFlight` 里发
  `GUIDE_HOLD` —— `GUIDE_HOLD` 的语义是「动画期间暂停」，恢复时长仍是 `idleDelay`，对不上 2 秒。

## 怎么验的

- `run_script_diagnostics`：TypeScript **0 错误**。
- 场景 diff 只有两处数值：`PrefillFlight.flyTime = 1`、`GuideController.prefillDelay = 2`；
  `idleDelay` 场景里本来就是 3，只改了代码默认值。
- 编辑器内存探针确认：`PrefillFlight.flyTime = 1`、`GuideController.idleDelay = 3 / prefillDelay = 2`，
  且 `GameIntro` / `FireworkReveal` 的原值没有被这次改动带走。

## 影响什么 / 还没验的部分

- 引导首次出现时间变为「预填揭晓结束 + 2s」，之后每次收掉再出现是 3s。
- **未跑预览**：1 秒飞行是否够慢、2 秒等待的观感需要实机确认；要再慢就继续加 `PrefillFlight.flyTime`。
- 关掉 `FireworkReveal` 时预填仍会抛 `PREFILL_DONE`（修复图直接出现），引导照样按 2 秒等待。
