# 香槟修复后小三改播 17 帧序列帧

- 日期：2026-10-21
- 提交：待回填
- 关联：AGENTS.md §5 / §6；docs/TUNING.md「小三换状态序列帧」

## 改了什么

- 新增 `assets/scripts/gameplay/SlotSequence.ts`：挂在一个带 `Sprite` 的节点上，监听 `PIECE_REPAIRED`，当触发槽位修好时按 `frames` 顺序播一遍，停在最后一帧；不建临时节点、不销毁、不换回静态图。
- `Canvas/GameLayer/小三1动作`：
  - 初始 `spriteFrame` 改为 `assets/recourses/小三动作序列帧/matte_00001.png`（原来停在末帧 `matte_00017`，会让修复瞬间从末帧跳回首帧）。
  - 新增 `SlotSequence`：`watch = Slot_02`（香槟 / pieceId 1），`frames = matte_00001 … matte_00017` 共 17 张，`frameInterval = 0.06`，`delay = 0`。
- `Canvas/GameLayer/Scene_BG` 上盯 `Slot_02` 的那个 `SlotSwap`：`hideNodes` 清空、`showNodes` 只留 `女主动作1/女主紧张表情`，不再引用已经不在场景树里的 `小三动作2`。
- `docs/ARCH.md` 增加 `SlotSequence.ts` 行；`docs/TUNING.md` 增加参数行，并把 `SlotSwap` 的「两个实例」改成三个实例。
- `tools/js/verify-scene.js` 的检查表加 `SlotSequence: ['watch', 'frames']`。
- 接线脚本：`tools/js/mount-small-three-sequence.js`（幂等，重跑不会重复挂组件）。

## 为什么这么改

- 用户要求用 `assets/recourses/小三动作序列帧` 展示香槟修复后「小三从一个状态变成另一个状态」。
- 原来的静态换节点方案依赖 `小三动作2`，但运行时场景树里已经没有这个节点；继续保留引用会在换节点时静默失败。序列帧末帧本身就是 `小三二` 的状态，播完停住即可，不需要再显示静态节点。
- 帧序：用 Pillow 对 17 帧和两张静态图做归一化像素差，`matte_00001` 与 `小三1动作.png` 最接近（11.92），`matte_00017` 与 `小三二.png` 最接近（16.09），所以按 1 → 17 播，起点改到第 1 帧。
- 没有复用 `RepairReveal`：那套是「在缺口位置临时建节点播序列帧」，这次要播的是场景里本来就摆好的小三，位置和生命周期都不同。

## 怎么验的

- `npx tsc --noEmit`：0 报错。
- `npm run check`：通过（仍只有原有的 `ProgressController.label` 为空告警；新增 `SlotSequence` 被检查到）。
- MCP 读回场景：`SlotSequence.frames.length = 17`，首帧 `matte_00001`、末帧 `matte_00017`，`watch = Slot_02`；`小三1动作` 的 Sprite 已是 `matte_00001`；盯 `Slot_02` 的 `SlotSwap` 只剩 `女主紧张表情`。
- 场景已用 `save-scene { force: true }` 落盘（默认的 `save-scene` 这次返回 false，强制存盘返回场景 uuid）；读 `assets/scene.scene` 确认序列帧 17 个 uuid 和 `SlotSequence` 都已序列化。

## 影响什么 / 还没验的部分

- 香槟修好前小三显示的是序列帧第 1 帧（原静态「小三1动作」）；修好后原地播约 1 秒，停在末帧（原「小三二」的状态）。
- `小三动作2` 不再被任何 `SlotSwap` 引用；场景文件里即使还残留这个 inactive 节点也不会再参与表现。
- 未跑预览/截图；17 帧的节奏、起始帧观感、以及「紧张表情在序列播放到 0.25 秒时淡入」的同步感，待实机确认。
- 若希望表情等序列播完再出现，把盯 `Slot_02` 的 `SlotSwap.delay` 从 0.25 调大即可，不用改代码。
