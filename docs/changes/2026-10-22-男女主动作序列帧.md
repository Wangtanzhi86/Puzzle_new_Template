# 男女主动作序列帧：等男主揭晓播完，再换人

## 改了什么

- `assets/scripts/gameplay/SlotSequence.ts` 新增三个 Inspector 项：
  - `hideUntilPlay`：播放前只关本节点的 `Sprite`，节点保持激活；
  - `waitShown`：不在吸附当刻起播，改等这一格的 `PIECE_SHOWN`（揭晓动画演完）；
  - `hideOnPlay`：起播那一刻把这些节点 `active = false`。
- `assets/scene.scene` 的 `GameLayer/男女主动作`：`watch = Slot_04`、10 帧、`frameInterval = 0.13`，勾上 `hideUntilPlay` / `waitShown`，`hideOnPlay = [Slot_04/Repaired, 女主动作二]`。

## 为什么这么改

- `SlotSequence` 是事件驱动的，不会把所在节点 `active = true`；如果为了“修好前不出现”取消节点激活，`onEnable` 不执行，组件永远收不到事件，看起来就是“没激活、没播”。
- `PIECE_REPAIRED` 在吸附成功当刻就发，男主揭晓（金色烟花 + 圆形扩散）还没演完；`PIECE_SHOWN` 才是这一格揭晓真正结束、修复图露面的时刻，所以起播点改为 `waitShown = true`。
- 到 `PIECE_SHOWN` 时，旧的 `Slot_04/Repaired` 和 `女主动作二` 要让位给 `男女主动作`，所以一并放进 `hideOnPlay`，在起播同一刻收掉。
- 否掉的方案：在 `SlotSequence` 里强行 `node.active = true`（会让节点开场就出现，且与“触发前隐藏”的意图冲突）；或给一个猜的 `delay`（不同揭晓类型时长不同，`PIECE_SHOWN` 才是准确信号）。

## 怎么验的

- 编辑器内按真实事件顺序跑：`onLoad → onEnable → onLevelBuilt → onRepaired(2)` 时 `playing = false`、`Slot_04/Repaired` 仍显示；再 `onShown(2)` 时 `playing = true`、`Slot_04/Repaired.active = false`、Sprite 打开、首帧 `matte_00001`；`update(0.3)` 后为 `matte_00003`。
- `npm run check` 通过；只剩原有 `ProgressController.label = null` 与背景九宫格 inset 未配两条提示。
- 未跑预览 / 未截图（按项目约定由用户验收）。

## 影响什么 + 还没验的部分

- `男女主动作` 在 `Slot_04` 的揭晓完整演完后才起播 10 帧序列，同时收掉 `Slot_04/Repaired` 与 `女主动作二`。
- `小三1动作` 的 `SlotSequence` 保持 `waitShown = false`、`hideOnPlay = []`，行为不变。
- 还没验：真机 / 预览里的实际起播时机；`Slot_04/Repaired` 被收掉后，若还有别的表现引用它，需要再确认。
