## 改了什么

- 场景 `Canvas/IntroLayer` 的 `GameIntro.video` 指回 `Canvas/IntroLayer/开头视频` 的 `EndVideo`，
  `GameIntro.region` = `Canvas`（同日后续已删），`GameIntro.skip = false`。
- `Canvas/IntroLayer/开头视频` 的 `cc.VideoPlayer.clip` 换成 `assets/recourses/开头视频.mp4`
  （uuid `2404b7c0-3507-41ea-bf15-10634c279e8e`，1.01MB，720×404，2.508s）。
- `EndVideo.fallbackTime` 12 → **5**，`fadeOut` 0.5 → **0.3**（片长短，12 秒兜底会让黑屏等太久）。
- `tools/js/mount-intro-video.js` 按当前 `GameIntro` 字段重写：只回填 `video / skip`，
  删掉早已不存在的 `left / right / slideTime / sweep`；片源与兜底参数可经 args 覆盖。
- `docs/VIDEO.md` 重写「开头视频」一节；`docs/STATUS.md` 的「点关开场」一句改为已恢复。

## 为什么这么改

- 老板要求「这个视频作为玩家点击关卡后播放的开场视频」：沿用现成的 `GameIntro` 卡片放大 +
  `EndVideo` 起播这条恢复路径，不新写播放器。
- `EndVideo` 的 cover / 首帧揭开 / 点一下跳过 / 被浏览器拦下自动静音 / DOM 元素收摊这一套已经踩过坑，
  换片只动 `VideoPlayer.clip` 一处。
- `fallbackTime` 改成 5 秒：新片只有 2.5 秒，自动播放被拦时不该按旧片的 12 秒继续压着画面。
- 否掉的方案：① 把 `skip` 重新勾上（老板这次明确要视频）；② 给开场单独写一个播放器
  （和结尾视频重复，且 DOM 视频的坑要再踩一遍）；③ 这次没有加 contain 模式 —— 片源是 720×404，
  按现有全屏 cover 会裁边，但「铺满还是留黑边」属于视觉决策，先按原设计接，等老板看构图再定。

## 怎么验的

- 跑 `node tools/exec.mjs scene tools/js/mount-intro-video.js "{\"clip\":\"2404b7c0-3507-41ea-bf15-10634c279e8e\"}"`，
  返回 `ok: true`，场景已存盘（UUID `bdd769ed-06ed-4ddc-86e0-54318ac1aeba`）。
- 解析 `assets/scene.scene` 复核：`VideoPlayer._clip` 的 uuid 是 `2404b7c0-…`；
  `GameIntro.video` 引用 `EndVideo` 节点、`region` 指 Canvas、`skip = false`；
  `EndVideo.fallbackTime = 5`、`fadeOut = 0.3`；视频节点 `_active = false`。
- 按老板偏好没有跑预览 / 截图，未做视觉自证。

## 影响什么 / 还没验的部分

- 片源 **720×404**，全屏 cover 到 720×1280 会**整幅宽度裁掉约 68%（左右各约 34%）**；若实际画面主体在两侧，
  需要改成 contain（留黑边）或 16:9 播放框 —— 这次没动。
- 视频是 DOM `<video>`，播放期间整屏触摸到不了画布，跳过只能靠引擎的 `CLICKED`；播完节点睡回去才恢复。
- 声音走视频自己的音轨，被浏览器拦下会自动静音重放；真机是否放行有声自动播放仍未验。
- 体积增加约 1.01MB × 1.25 ≈ **1.26MB HTML**，交审前要重新核 < 5MB。
- 未跑预览 / 未刷新资源库；编辑器预览若仍跑旧类，需要 refresh assets。
