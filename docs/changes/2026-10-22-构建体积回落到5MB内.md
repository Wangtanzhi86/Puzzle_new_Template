# 打包体积回落到 5MB 内：默认 WebP 质量 94/92 → 90/86

- 日期：2026-10-22
- 提交：<提交后回填>
- 关联：AGENTS.md §9、docs/RELEASE.md §8.5

## 改了什么

- `tools/pack-playable.mjs:55` 的默认 `uiQuality` / `photoQuality` 从 **94 / 92** 改为 **90 / 86**；
  文件头用法说明同步。
- 不改引擎、不改构建配置、不改任何美术源文件，只改打包期 WebP 有损质量。

## 为什么这么改

- 2026-10-22 编辑器构建报 `[playable-builder] 打包失败（退出码 1）`，根因是体积：
  - `build/web-mobile` 175 个文件、6.73MB；
  - q94/92 的 WebP 只省 0.78MB，拼完 HTML **5.15MB**；
  - 三个通道全部 `❌ 超了 5MB 上限 0.15 MB`，不是某个通道单独的问题。
- 试了三档（`--report`）：90/86 → 4.82MB；88/82 → 4.58MB；85/78 → 4.40MB。
  选 **90/86**，在保住观感的前提下留 0.18MB 余量；没有直接跳到 85/78。
- 否掉的方案：
  - 只在命令行加 `--ui-quality`：编辑器 hook 调用打包器时不传质量参数，默认值不改就还会失败；
  - 删素材 / 重压结尾 mp4 / 改 5MB 上限：前两者改动面大且影响玩法，后者违反投放红线。

## 怎么验的

- `node tools/pack-playable.mjs --build build/web-mobile` → **EXIT 0**。
  - WebP：51 张，省 1.04MB，5.69MB；
  - AppLovin / Moloco / Google 三份均 **4.82MB**，均显示 `✅ 在 5MB 上限内，余量 0.18 MB`；
  - 启动闸门、CTA 明文、零外链、Google 白名单外链等自检全过。
- 仍有一条既有警告：产物里有 4 处 `XMLHttpRequest` 字面量，Moloco 暂时别传；它不影响本次构建通过。

## 影响什么 / 还没验的部分

- 之后所有默认打包（含编辑器 onAfterBuild）都用 90/86，不会再次因这 0.15MB 失败；
  单独出高质量版本仍可显式传 `--ui-quality` / `--photo-quality` 或 `--tag`。
- 有损压缩的观感（UI 文字边缘、角色序列帧）本次没有截图/人眼比对，也未上真机验证 WebP 解码；
  若觉得糊，可把默认回调到 92/88 并同时裁素材，但会再次逼近 5MB。
