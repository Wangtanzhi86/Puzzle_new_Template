# 槽位 2 吸附后物品渐隐

- 日期：2026-10-21
- 提交：待提交
- 关联：AGENTS.md §6 / docs/TUNING.md

## 改了什么

- `Slot_02` 的 `PieceSlot.hideOnRepair` 置为 `true`：吸附当刻不走任何揭晓，破损图 / 修复图在 `swapFadeTime`（当前 0.25s）内轻微放大并淡出，淡完再抛 `PIECE_SHOWN`。
- 该格没有配 `swapHide` / `swapShow`，所以只渐隐、不换节点；`swapDelay` 不参与。
- 新增幂等接线脚本 `tools/js/set-slot2-fade.js`（只改这一个布尔，保留 Inspector 里的时长）。
- `docs/TUNING.md` 的「吸附后整格隐藏」与「换节点延迟」两行改为当前实际的 `Slot_02`，并说明没配换节点时不读 `swapDelay`。

## 为什么这么改

- `PieceSlot` 已有 `hideOnRepair` 这一支，行为就是「收掉这一格、跳过全部揭晓、渐隐后算露面」，不需要再写组件或新事件。
- 否掉的方案：单独加一个 `FadeAfterSnap` 组件。它要和 `repair()` 的揭晓顺序、`PIECE_SHOWN` 计数、引导暂停全部重新对齐，收益只有「可配时长」，而现成的 `swapFadeTime` 已经够用。
- 没有配 `swapHide` / `swapShow`，是为了避免误触发换人；这一格只要「物品消失」。

## 怎么验的

- 通过 MCP 执行 `tools/js/set-slot2-fade.js`，回读 `Slot_02`：`hideOnRepair = true`、`swapFadeTime = 0.25`、`swapHide / swapShow = null`，场景已存盘（UUID `bdd769ed-06ed-4ddc-86e0-54318ac1aeba`）。
- 读代码确认 `repair()` 的 `hideOnRepair` 分支在 `fireworkReveal` / `stickerApply` / `brushReveal` / `circleReveal` 之前，因此这一格原有的烟花揭晓会被跳过。

## 影响什么 / 还没验的部分

- `Slot_02` 修好后整格消失，原本配在这一格的揭晓不再播放；`PIECE_SHOWN` 晚 `swapFadeTime` 秒，进度与完成计数不受影响。
- 未跑预览：0.25s 的渐隐是否够明显、消失后露出的背景是否合适，需要实机确认；要调时长就改 `Slot_02` 的 `swapFadeTime`。
- 本次按节点名把「槽位 2」理解为 `Slot_02`（香槟杯那格，也是池序第 1 块）；若指的是池序第 2 块 `Slot_03`（渣男），把脚本里的 `Slot_02` 换成 `Slot_03` 重跑即可。
