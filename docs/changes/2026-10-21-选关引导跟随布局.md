# 2026-10-21 选关引导手指跟随长屏布局

## 改了什么

- `assets/scripts/ui/LevelGuide.ts`：
  - `onEnable` 不再立刻 `play()`，先藏手，`scheduleOnce(restart, 0)` 等一帧布局落定再起播。
  - 新增 `screen.on('window-resize', ...)` / `off`：窗口尺寸变化后停掉旧 tween，再等一帧按第一关的新世界坐标重摆手指。
  - `pause` 同时撤掉待执行的 `restart`，避免玩家已经按住时手又弹出来。
- 场景与 `LevelGuide.offset` 都没动：`target` 仍是 `Canvas/Change/ScrollView/view/content/Level_01`，`offset` 仍是 `(80, -60)`。

## 为什么这么改（含否掉的方案）

- 长屏下 `Canvas/Change/ScrollView/view/content` 的 `Widget` 会把 `content` 顶边贴到 `view` 顶边，第一关随之上移。
- `LevelGuide.onEnable` 原来立刻读 `target.worldPosition` 并建 `repeatForever` tween；此时首帧 Widget 对齐还没跑完，读到的是设计稿 1280 下的旧位置。tween 的起止点是值快照，布局随后再动也不会跟着改，于是手指停在偏下的旧位置。
- 不是 `offset` 配错：把旧位置和 `offset` 相加的结果正好等于现场看到的那只手的落点；也不是 `target` 绑错，绑定一直是 `Level_01`。
- 否掉的方案：在 `play()` 里轮询 `target.worldPosition` 改 tween 终点 —— Tween 不支持改目标值，只能重建；不如等布局稳定后重建一次，并在窗口 resize 时重建。

## 怎么验的

- `npx tsc --noEmit`：0 报错。
- `npm run check`：通过；仍只有原有的 `ProgressController.label` 为空告警。
- 未跑预览 / 真机；长屏首帧手指位置与转屏后的跟随效果待实机确认。

## 影响什么 + 还没验的部分

- 只影响选关界面的 `LevelGuide`；游戏内 `GuideController` 没动。
- 窗口 resize（含横竖屏切换）会重摆手指；如果运行期有“不触发 window-resize 的布局变化”，仍需再手动 `play()`。
- `Canvas/Change/Guide/Finger` 在编辑器里摆的坐标仍只是占位，运行时会被 `LevelGuide` 覆盖。
