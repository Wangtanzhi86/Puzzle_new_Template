# 预填槽位补演：开场后碎片飞进缺口再揭晓

- 日期：2026-10-20
- 提交：<待回填>
- 关联：AGENTS.md §1.4 / §5 / docs/STATUS.md

## 改了什么

- 新增 `assets/scripts/gameplay/PrefillFlight.ts`：挂在 `EffectLayer`，`GAME_START` 时先把预填格同步退回破损态，
  再按 `delay + i * stagger` 让一块碎片从 `PiecePoolLayer` 飞到该格缺口中心；落点后调 `PieceSlot.playPrefill()`
  走这一格的揭晓（有 `FireworkReveal` 就是金色烟花 + 圆形扩散）。
- `PieceSlot` 新增 `resetPrefill()` / `playPrefill()`：前者只把画面退回破损态（`_repaired` 不动），
  后者演完收掉破损图并抛新事件 `GameEvent.PREFILL_DONE`。
- `RepairSystem` 不再在建关时给预填格补进度：改成收到 `PREFILL_DONE` 才 `+1`，所以碎片还在飞的时候进度条不动。
  `PIECE_REPAIRED` 仍只在真实吸附时发，`EndgameCta` 的 `winCount` 计数不受影响。
- 场景：`EffectLayer` 挂 `PrefillFlight`，`from = PiecePoolLayer`（`tools/js/mount-prefill-flight.js`，幂等）。
- `verify-scene.js` 增加两条：有 `prefilled` 槽位但没挂 `PrefillFlight` 会报；四种「整格接管」揭晓
  （金色烟花 / 贴纸 / 画笔 / 圆形）同时配多个会报。
- 文档：AGENTS 事件表补 `PREFILL_DONE`，ARCH 补 `PrefillFlight` / `SlotSwap` / `FireworkReveal`。

## 为什么这么改

- **不能在 `LEVEL_BUILT` 当场演**：那时 `IntroLayer` 还盖着整屏（卡片放大段），演了没人看见。
- **必须赶在 `GAME_START` 同一帧退回破损态**：`GameIntro.finish` 是「藏掉开场层 → 立刻发 `GAME_START`」，
  晚一帧玩家就会先看到修好的图、再看到它碎回去。复位放在事件处理里同步做，飞行才延后。
- **碎片要在 `EffectLayer` 里飞**：`GameLayer` 挂了 RECT Mask，从池子飞向缺口的途中会被裁掉；
  `EffectLayer` 是 `GameLayer` 的兄弟层。`PieceSlot` 不持有层引用，所以由全局组件统一建 / 收飞行节点。
- **进度等演完再走**：否则玩家看到碎片还在半空、进度已经 +1。预填格也**不能补发 `PIECE_REPAIRED`** ——
  那是 `EndgameCta` 数 `winCount` 的依据，补一发等于开局白送一格。
- 否掉的方案：① 把预填逻辑整个删掉、让 Slot_01 当普通碎片 —— 会和「槽位1开局已修好」的换图 / 换人联动冲突；
  ② 直接给 `PieceSlot` 加「特效层」引用 —— 槽位与层耦合，且每个槽位都得配一次。

## 影响什么 / 还没验的部分

- 预填格的开场表现改了：开局进度从 **0/4** 起，约 1.5s（延迟 .15 + 飞行 .55 + 烟花 .18 + 扩散 .6）后到 **1/4**；
  之后照旧，第 3 块真实吸附时到 4/4 并跳商店。
- **未跑预览 / 未看画面**：飞行的速度、起飞点是否够自然、烟花与扩散的衔接需要真机或预览确认；
  想调就改 `PrefillFlight` 的 `delay / flyTime / stagger / fadeTime`。
- 若关掉 `FeatureFlags.fireworkReveal`，补演会退化成「飞到位后修复图直接出现」，没有金色烟花。
- `docs/STATUS.md` 的 23 槽表格与当前 `assets/scene.scene`（4 槽）不一致，本次没有整表重写；以场景实测为准。
