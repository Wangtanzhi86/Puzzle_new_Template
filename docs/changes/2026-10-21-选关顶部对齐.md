# 选关滚动内容顶部对齐（长屏不再下坠）

## 改了什么

- 场景 `assets/scene.scene`（UUID `bdd769ed-06ed-4ddc-86e0-54318ac1aeba`）：
  `Canvas/Change/ScrollView/view/content` 新增 `cc.Widget`：
  `isAlignTop = true`、`top = 0`、`isAlignBottom = false`、`isAlignVerticalCenter = false`、
  `alignMode = ON_WINDOW_RESIZE`。正常 720×1280 下 `content.position.y` 仍是 550。
- 新增幂等接线脚本 `tools/js/fix-level-scroll-top.js`。
- `tools/js/mount-level-select.js` 重建 content 时一并挂这个 Widget，避免以后重建选关把修复冲掉。
- `docs/ADAPT.md` §7.1 补一条「选关 content 顶边靠 Widget 跟」。

## 为什么这么改（含否掉的方案）

- 根因不是 `ScrollView` 的 90 顶边距，而是 **content 的 y 写死**：content 锚点在顶，
  但 `content.position.y = 550` 是 1280 稿下 `view` 高度 1100 的一半。
  长屏走 `FIXED_WIDTH` 把 `view` 拉到 1400 时，content 仍停在 550，顶边就多出 `(1400-1100)/2 = 150`
  的空隙，屏幕越长坠得越多。
- 采用 Widget `top = 0` + `ON_WINDOW_RESIZE`：只在画布策略变化时把 content 顶边贴回 view 顶边。
- 否掉 `ALWAYS`：每帧都会把 content 按顶边摆回去，和 ScrollView 的滚动量打架。
- 否掉「直接把 `ScrollView.top` 从 90 改小」：90 那圈是留给刘海/状态栏的，而且改小只缩短固定边距，
  长屏那段随高度增长的漂移还在。

## 怎么验的

- MCP 读回：content 有 `cc.UITransform / cc.Layout / cc.Widget`，`top=0`、`mode=2`、
  `alignTop=true`；编辑态 `y=550`。
- 同场景临时把 `view` 高度改成 1400（`--no-save`），手动 `updateAlignment()` 后
  content `y=700`，即顶边与 view 顶边重合；已恢复 `y=550` 并重新存盘。
- `npm run check` 通过，仅剩原有的 `ProgressController.label` 为空告警。

## 影响什么 + 还没验的部分

- 只影响选关列表的纵向起点；`ScrollView` 的 90 顶边距、卡片尺寸与网格布局都没动。
- 未跑真机/预览：长屏（如 720×1560）下首行是否正好落在 90 + 24 的位置、以及转屏时
  `ON_WINDOW_RESIZE` 的对齐时机，需在 Game View / 真机确认。
