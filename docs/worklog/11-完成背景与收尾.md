## 完成背景复用「画笔涂色」+ 笔头走到哪撒到哪的魔法仙尘（2026-10-15）

**要的是什么**：全部修完之后那一屏（原来是「完成背景从中心圆形羽化扩散」，`bg-reveal.effect`）
换成**和单块修复同一支画笔** —— 圆头笔从左上角斜着来回刷到右下角，刷过的地方才露出完成图；
笔头走过的地方撒一层「魔法仙尘」（粒子多一点、亮一点），整个过程配 `魔法光粒.MP3`。

**场景侧**（`tools/js/mount-scene-bg.js`）：`GameLayer/Scene_BG` 下面两个同尺寸子节点 ——
`完成背景`（Sprite `成图`，一个 `SceneBgSwap.revealView` 口，**平时 `active = false`**）与
`魔法仙尘`（`ParticleSystem2D`，一个 `SceneBgSwap.dust` 口）。`SceneBgSwap` 还把 `brushEffect`
指到 `brush-reveal.effect` 上。

### 四个值得记下来的点

**一、涂完把贴图挪走，不留一层常驻的透明覆盖。**

`完成背景` 是挂在材质上的（`customMaterial` 只在刷的过程中有意义）。刷完 `finish()` 把它的
`spriteFrame` 拷给 `Scene_BG` 自己，然后 `abort()` 把材质销毁、节点 `active = false` 收掉。
最终画面就是**一个节点、一张不透明的底图** —— 一帧不透明覆盖省掉的是每帧一次全屏混合，
而且转屏 / 改窗口尺寸时那层覆盖和 `Scene_BG` 各自吃 Widget，留两层迟早有对不齐的一帧。

**二、笔头位置的几何在 TS 里复述了一遍（`headOf()`）。**

材质是在 GPU 上算「哪些像素刷过了」，粒子节点得在 CPU 上知道「笔尖在哪」，两边必须一致。
`headOf()` 就是把 `brush-reveal.effect` 里那段路径**抄了一遍**：像素坐标 `p = (uv.x·A, 1-uv.y)`、
第 i 笔是 `u + t = d`（`d = (i + 0.5)·2/K`）这条 45° 斜线的一段、各笔按 `min(d, 2-d)·diag` 加权依次首尾相接。
⚠️ **改一边必须改另一边**（`BRUSH_MAX_ROWS = 12` 也是两边各一份）。

**三、加色混合只能运行期改，因为 `ParticleSystem2D` 的 blend 不是 `@property`。**

「亮一点」在粒子自己的颜色上做不全 —— 普通 alpha 混合叠出来是灰的，要的是**加色**。
`ParticleSystem2D` 的混合模式没有 Inspector 口、也存不进场景（和 `Layout` 那个对齐勾同一类问题），
只能在拿到材质实例之后改混合状态，写法照抄引擎的 `UIRenderer._updateBlendFunc()`：

```ts
const state = this.dust.getMaterialInstance(0).passes[0].blendState;
const target = state.targets[0];
target.blend = true;
target.blendSrc = gfx.BlendFactor.SRC_ALPHA;
target.blendDst = gfx.BlendFactor.ONE;
state.setTarget(0, target);
```

⚠️ **`cc.BlendFactor` 是 `undefined`**，得走 `cc.gfx.BlendFactor`（`SRC_ALPHA = 2`、`ONE = 1`）——
编辑器里现读确认过，别按文档猜。另外 `ParticleSystem2D` 那些可序列化字段是**构造函数里赋的实例字段**，
不在原型上（所以探针读原型会是空的），`playOnLoad` / `positionType` 这类只能用场景里的节点读。

**为什么不在场景里配**（本来以为能，编辑器里现读否掉了）：场景里确实存着 `_srcBlendFactor` / `_dstBlendFactor`
两个字段（`mount-scene-bg.js` 建完节点时是 `2 / 4`，就是普通 alpha），但**只有 `srcBlendFactor` 有访问器**，
`dstBlendFactor` **在整条原型链上都不存在** —— 赋值 `dust.dstBlendFactor = 1` 不报错、读回来还是 `1`，
而引擎真正吃的 `_dstBlendFactor` **纹丝不动还是 4**（等于往实例上挂了个谁都看不见的普通属性）。
加色要的两个因子一真一假，走场景配置只能是半套，所以老老实实改材质实例。

**四、粒子贴图不引美术资源也能跑。**

仙尘那张图还没有。`TrailEmitter` 里原本有一份「代码画个径向衰减的白点、转成 `SpriteFrame`」的私有实现，
这次把它抽成 [assets/scripts/core/DotTexture.ts](../../assets/scripts/core/DotTexture.ts)（`makeDotFrame()`），拖尾与仙尘共用。
`SceneBgSwap.onLoad` **只在 `dust.spriteFrame` 空着时**才塞这个兜底 ——
美术出了仙尘图，直接拖到那个粒子节点的「SpriteFrame」上就行，代码不用动。

### 一个被测序坑到的：场景里的老值会盖掉新默认值

`SceneBgSwap` 上一版是圆形扩散，它有 `revealTime = 0.9` / `feather = 0.35` 两个 `@property`。
这一版还叫这两个名字（`feather` 在画笔里是「羽化相对半径」，含义接近但不是一回事）。
结果：`addComponent` 之后一读，`rows` / `radius` 是新默认值（`5` / `0.3`），
`feather` 却是 **`0.35`** —— **反序列化是按属性名往实例上赋值的，场景里存着的老值优先级高于类默认值**。
所以 `mount-scene-bg.js` 里补了一句「第一次接画笔时把 `revealTime` 与 `feather` 一起改掉」（由
`comp.brushEffect !== brush` 判定「第一次」）。**同名的 `@property` 换了含义时要主动覆盖，别指望默认值生效。**

### ⚠️ 还没验的部分

只在编辑器里核了接线（`mount-scene-bg.js` 回读 `revealView = 完成背景` / `dust = 魔法仙尘` /
`brushEffect = brush-reveal`，`verify-scene.js` 也没报新的），**Game View / 真机都没跑过**。要过的是：

1. **画笔那 1.2 秒（`revealTime`，在 `SceneBgSwap` 上）和 5 行（`rows`）在 582×840 这个框上排得下** ——
   `radius = 0.3` 对 5 行够（当初按 `1.45 ÷ 5 = 0.29` 算的），改行数记得跟着改半径。
   ⚠️ 2026-10-15 已改成 **12 行 / 0.08 / 2.5s**，那个 1.45 的下限规则也是错的，见下一节；
2. **仙尘是不是跟着笔尖走**（`headOf()` 那套几何抄错没抄错，看的是粒子带而不是笔迹）；
3. **亮不亮**：加色叠出来是过曝还是不够 —— 不够就调粒子节点的 `startColor` / `emissionRate`，
   不用改代码；
4. **`END_SHOW` 到不到**：这条路现在是 `winCount = 0` 时的**主路径**，`SceneBgSwap` 演完才抛
   `END_SHOW`，卡住就是整条广告永远不出结束界面（`brushEffect` 或 `revealView` 为空时它直接抛，
   不会卡，别被这个兜底麻痹）。

## 三件表现调整：接管后不演脉冲 / 完成背景笔头调细 / 揭角按形状逐格配（2026-10-15）

用户原话：「1、自动打关过程碎片放置后不用缩小再放大这个效果了。2、最后显示完成背景时一开始涂抹的
面积太大了，先只涂一点，也就是整个涂色的流程长一些。3、所有碎片的揭角设置现在都是一致的，你针对性的
做一下修改，根据碎片的长宽比以及大小来针对性的设计每个碎片的掀起的比例以及掀那个角，比如长的就掀
右下角，宽的就掀右边」。三件都是**表现层**，玩法一行没动。

### 一、接管之后不演「贴纸收尾脉冲」

**为什么**：那一下（修复图先缩一点淡下去、再放大回来）单块看是「贴好了」的反馈，
但接管之后是**一屏 3 块同时落**、每块各缩各淡、0.2 秒一收一放叠在一起，就是一片闪。

**怎么接的**：`StickerApply` 收一个 `AUTO_PLAY` 监听，`settle()` 里多一个条件：

```ts
if (this.pulseEffect && !this._auto) this.runPulse(node, handle.onApplied);
else handle.onApplied();
```

`_auto` 一发即真、不回头（接管之后不会再交还玩家）。**发射方一行没动** ——
`AUTO_PLAY` 是自动打关那轮本来就有的（§5），这里只是多挂一个监听方，符合「事件与发射方一律不动」。
玩家自己放的那 `afterPlaced = 3` 块照旧演脉冲。

⚠️ `onApplied` 是「这一格真正算露面」的回调（扫光 / 总修复计数 / `PIECE_SHOWN` 都按它走），
跳脉冲也必须把这一句原样发出去，不能 `return` —— 少发一次最后一格就永远不露面、`END_SHOW` 也就到不了。

### 二、完成背景那支画笔：笔头调细 + 流程放长

**要的是什么**：「一开始涂抹的面积太大了，先只涂一点」。

**病因**：`brush-reveal` 起笔那一瞬是个**半径 = `radius` × 高度**的圆，而 `SceneBgSwap` 上的
`rows = 5 / radius = 0.3` 是照**碎片**尺寸定的（`AGENTS.md` §16 旧行）—— 搬到 582×840 的完成背景上，
起笔那团半径就是 `0.3 × 840 = 252px`、**直径占画面宽度的 87%**，一上来就糊掉半张图。
（单块碎片没这个问题：那张图本身只有一两百 px 高。）

**改法**（`tools/js/set-scene-brush.js`，幂等、可重跑）：`rows = 12`（材质 `BRUSH_MAX_ROWS` 的上限）、
`radius = 0.08`、`revealTime` 从 1.2 抬到 **2.5**。笔头半径 67px、直径占画面宽 **23%**（原来是 87%），
笔数从 5 涨到 12 笔，看着才像在「刷」而不是「糊」。

**半径不能随便降 —— 下限是量出来的，不是读代码读出来的**：低于「相邻笔迹不留缝」的下限，
笔迹之间会露出一条条没涂到的底。把 `brush-reveal.effect` 的判定抄成普通 JS 逐像素扫了一遍
（420×600 采样点，把「实心缺口 = 0」的下限扫到 0.002 的精度）：

| 底图长宽比 A | 下限 × 笔数 |
|---|---|
| 0.3 | 0.46 |
| 0.5 | 0.62 |
| **0.69（本图 582×840）** | **0.74** |
| 1（正方） | 1.01 |
| 1.5 | 1.08 |
| 2 | 1.25 |
| 3 | 1.42 |

- **跟笔数是干净的倒数关系**：A≈0.69 时 K = 3/5/8/10/12 五档的「下限 × K」全部落在 0.73–0.74。
- **常数只跟底图长宽比走**（越方的图越费：相邻两笔的垂直间距按 `dd × A ÷ √(1+A²)` 变，A 越大越宽，
  而方图四个角又只有圆头笔端盖得到）。
- ⚠️ **AGENTS.md 里那个「得 ≥ 1.45÷行数」是错的，大一倍**（同一个 A 下实测 0.74）。
  已改成实测值，`BrushReveal.ts` / `SceneBgSwap.ts` 两个 tooltip 与 §16 两行一并更正 —— 照 1.45 配
  等于白扔一半的笔头细节（单块碎片那边是 5 笔 0.3，按新规则竖长碎片只要 0.15；类默认值已经从
  0.3 收到 0.25 —— 那一路的碎片长宽比能到 1.078，方的那个下限是 `1.01 ÷ 5 ≈ 0.2`）。
- 目前取 **0.08**（下限 0.062，留 ~30% 余量）：素材边缘有 `feather` 羽化，贴着下限配边界会发虚。
- 想再细只能**先改材质**：12 是 `BRUSH_MAX_ROWS` 那个循环的上界，笔数封在 12，半径就降不到 0.062 以下。

⚠️ **`revealTime` 别为「再长一点」堆到 3 秒以上**：`winCount = 0` 时这段是**主路径**，
演完才抛 `END_SHOW` 亮结束界面，拖多久玩家就等多久才看见 CTA。

### 三、揭角按每格的形状配（21 格右下角 / 2 格右边）

**要的是什么**：「所有碎片的揭角设置现在都是一致的……根据碎片的长宽比以及大小来针对性地设计」。

**病因**：23 格原来抄的是同一份（掀右下角、`liftRatio = 0.25`）。可碎片从 **17×34** 到 **431×140** 都有：

- 比例落到 171×775 的长条上，折线离角 167px —— 掀掉一整块；
- 落到 17×34 的小碎片上只有 9px，等于没掀。
- 折线高光带宽还写的是「**相对碎片高**」，775 高的长条上光带就有 39px，比折线本身还厚，整块糊成高光。

**改法**（`tools/js/set-slot-peel.js`，逐格现算、幂等）：

1. **掀哪个角**：宽 ÷ 高 ≥ **1.2**（宽扁的）掀**右边**，角取右边缘中点 `(1, 0.5)`；
   其余（竖长的、近正方的）掀**右下角** `(1, 0)`。
   - 这里吃到一个现成的好处：`StickerPeel.peelLine()` 的 `corner` 是**归一化坐标上的任意一个点**，
     不要求是角（`u = normalize((0.5, 0.5) - corner)` 才是它的方向）。
     取 `(1, 0.5)` 得到的方向是纯水平，折线是一条**竖线**，整条右边缘翻过去 —— 不需要新代码。
   - 当前 21 格右下角；`Slot_15`（205×167）与 `Slot_23`（463×150）掀右边。
2. **掀起多少**：先定折线的**绝对深度** `d = 0.28 × 短边`（世界 px），再折成 `peelLine` 要的比例 ——
   它要的 `amount` 是「沿角 → 对角那个方向推多远」，而那个方向上的跨度是 `span = |ux|·w + |uy|·h`，
   所以 `liftRatio = d ÷ span`。这样无论碎片多大，**掀起来那块占短边的比例是一样的**
   （深度固定，比例值摊在 0.066–0.228；实测 `Slot_08` 184×833 → 深度 51.5px / 比例 0.072，
   原来同一个 0.25 落到它头上是 167px）。
3. **折线高光带宽**同步按 `d` 折算：`creaseWidth = 0.22 × d ÷ h`。

⚠️ 它会**覆盖**每格手调过的值 —— 换美术、碎片尺寸变了就重跑一次。同一份脚本顺手把 `StickerApply`
上那 6 个抄写值同步成全局那份（现在 23 格全勾了单独配，那 6 个值没人读；但不一致 `verify-scene.js`
会报一条）。**别为了消这条告警去跑 `mount-sticker-apply.js`** —— 它会顺手把槽位的 `brushReveal` 清掉。

⚠️ **还没在 Game View 里看过**：折线角/深度是算出来的、不是摆出来的，要看的是
① 长条碎片（`Slot_08` 之类）掀起来那块会不会显小、② 宽扁那两格「掀整条右边」的观感、
③ 同一屏 3 块同时揭角会不会因为角度不同而显得散。三个数（`DEPTH` / `BAND` / `WIDE`）
都在 `set-slot-peel.js` 顶上的常量里，改完重跑。

## 收尾：最后一批齐落 → 定格 → 一道光横扫 → 再开画笔（2026-10-15）

原话是「**最后一批碎片的效果更明显一点，有明显的结束效果**」。当时的处境：最后一批落地之后
**什么特别的都没有** —— 最后一格贴平演完（0.35s），同一拍画笔就开始刷，读起来只是「又修好一块
+ 一张图自己刷出来」，没有任何「到此为止」的拍子。

### 手里已经有什么

- `RepairSweep` 里**本来就写着**「全部修完扫所有槽位的并集、共用同一条世界坐标轴，一起走同一个
  进度，读起来是一道光横扫全场」—— 那正是收尾要的那一下。它一直**关着**，原因就是**它和画笔
  同一拍开演会撞**（两者都挂在最后一个 `PIECE_SHOWN` 上）。
- 所以收尾**零新资源**：把已有的那道扫光按正确顺序放出来，中间垫一口留白就够了。

### 落地的三拍（时间轴从「最后一格露面」= 最后一个 `PIECE_SHOWN` 起算）

| 时刻 | 演什么 | 归谁管 |
|---|---|---|
| 0 → 0.5 | **什么都不演**（定格） | `RepairSweep.completeDelay = 0.5` |
| 0.5 → 1.4 | **一道光横扫整块拼图**（23 格并集） | `FeatureFlags.sweepOnComplete` + `RepairSweep.completeTime = 0.9` |
| 1.4 → 3.9 | **画笔把完成背景刷出来** + 仙尘 → `END_SHOW` | `SceneBgSwap.delay = 1.4` + `revealTime = 2.5` |

外加**最后一批齐落**：`AutoPlayer` 在 `step()` 里判断「这批里装着最后一格」就整批同时起飞
（`stagger` 归零），前面一批一批错着走、收尾这一下齐刷刷落地，靠节奏对比再垫一层。
判据用的是**槽位下标**（`batch.some((e) => e.slotIndex === this._data.length - 1)`）而不是
「块数够不够」—— 玩家先手修了几块、`batchSize` 除不除得尽都不影响这个判断。

### 两个实现上的选择

1. **定格为什么记在 `RepairSweep` 上，而不是 `AutoPlayer` 上**：留白要发生在「整张图**看起来**
   已经完整」那一刻，也就是最后一格自己那 0.35s 的贴平演完之后 —— 那正好是 `PIECE_SHOWN`。
   放在 `AutoPlayer` 的落地回调上会变成「碎片落下了、贴纸还在翘着，画面就僵住 0.5 秒」。
   顺带好处：玩家自己修完最后一块走的也是同一段收尾，两条路一致。
2. **两个延时为什么凑不齐成一个数**：扫光和画笔分属两个组件，§5 不让加事件名、§4 也不许跨模块
   拿引用 ⇒ **没有任何通道能告诉画笔「扫光演完了」**，只能各配一个延时，靠
   `SceneBgSwap.delay = RepairSweep.completeDelay + RepairSweep.completeTime` 这条约定对齐。
   这不是随手写的常数，所以给它配了三道保险：两个 `tooltip` 里互相点名、
   `tools/js/set-finale.js` 成对写、`verify-scene.js` 里一条专门盯它俩的检查
   （短了两道叠一起、扫光关着还留着 delay 都报）。

### ⚠️ 还没验 / 需要留意

- **没在 Game View 里看过**。看点是：① 0.5s 的定格会不会显得像卡住（不像留白像掉帧）；
  ② 扫光扫过 23 格并集时，散布在整块拼图上的 23 个独立小 Sprite 会不会因为「每块各自一个
  quad、共用一个轴向归一化」而露出接缝；③ 3.9 秒对一条试玩广告偏长。
  不合适就改那一对延时（`set-finale.js` 里是 `HOLD` / `SWEEP` 两个常量）。
- **「齐落」现在等于没改**：场景里 `stagger = 0.01`（10ms），本来就看不出错峰，
  所以归零和不归零画面上一样。想要这一下有意义，得先把 `stagger` 调到 0.1 上下。
  代码里的判断留着 —— 它是条定则（最后一批同时落地），不是随手写的数。
- **「一次飞两批」之后，最后一批只剩 2 块**（23 格里玩家先手 3 块 ⇒ 剩 20 块，按 6/6/6/2 切）。
  齐落的声势比「一屏一屏」（最后一屏 2 块，一样）没变，但**前面几批变大了**，
  节奏对比反而更弱。要更强的话两条路：把 `batches` 调回 1（收尾两块的对比更明显），
  或者最后一批单独按 `batchSize` 切（要动 `step()` 的切法，现在没做）。
- **`winCount > 0` 的老路上整段演不到**（商店在最后一块**吸附当刻**就开了，比 `PIECE_SHOWN` 还早）。
  现在 `winCount = 0` 所以它在主路径上，**代价是通往 CTA 的时间多了 1.4 秒**。
- `魔法光粒`（`LAST_SHOWN` 那条音频）听的是最后一个 `PIECE_SHOWN`，**不是**画笔开演 ——
  加了 `delay` 之后它落在**扫光开演那一拍**，比画笔早 1.4s。听感上更像「收尾开始」的音效，
  但它当初配的意思是「画笔开演」（见「音频改版」那节），要改回画笔那拍得另想办法。

## 结尾视频：完成背景演完先播一段，再亮结束界面（2026-10-15）

**要什么**：`winCount = 0` 那条主路径上，`SceneBgSwap` 画笔刷完成背景、抛 `END_SHOW` 之后，**不要立刻弹结束界面**，
先在拼图区（`Canvas/GameLayer/Scene_BG` 那个框）铺满播一段视频，播完（或玩家点一下）再让 `CtaController` 亮界面。

**实现**：照着 1013 分支「失败动画」那套搬（`platform/FailVideo.ts` → 改成 `platform/EndVideo.ts`）。
**没有加事件名、没有动发射方**：改的是 `END_SHOW` 的消费方 —— `CtaController` 从 `EventBus.on(END_SHOW, this.show)`
改成 `this.onEndShow`，里头先 `endVideo.play(cb)`，播完才 `show()`；没配视频 / 没配播放器就当场 `show()`（退路）。

搬过来的三件（**少任一件都会在单文件产物里炸，而编辑器里看不出来**）：

1. `tools/runtime/playable-runtime.js` 拦 `HTMLSourceElement` —— 引擎给 `<video>` 建的是子节点 `<source>`，
   地址写在 `source.src` 上，而 `HTMLSourceElement` 不继承 `HTMLMediaElement`，只拦后者等于没拦；
2. `mediaTypeFor()` 给 `.mp4` 的 blob 补 `type: 'video/mp4'` —— Safari 对无 type 的 blob 视频直接
   `MEDIA_ERR_SRC_NOT_SUPPORTED`，Chrome 能嗅探所以本地测不出来；
3. `settings/v2/packages/engine.json` 把 `video` 从关改开（`_value` + `includeModules` 两处，§9 那条「必关」现在是「唯一例外」）。

**片源怎么挑的**（三个候选，用 mp4 box 解析量的，没有 ffprobe）：

| 片源 | 大小 | 时长 | 码率 | 分辨率 | 比例 | 对区域 0.6933 | 进 HTML |
|---|---|---|---|---|---|---|---|
| `结尾视频.mp4`（旧，没用） | 3.34MB | 5.06s | 5542kbps | 834×1112 | 0.750 | 左右各裁 3.8% | +4.18MB（**必超**） |
| **`结尾视频3：4.mp4`（采用）** | **0.84MB** | 3.88s | 1827kbps | 480×640 | **0.750** | **左右各裁 3.8%** | **+1.06MB** |
| `结尾视频9：16.mp4`（备选） | 1.50MB | 2.95s | 4259kbps | 720×1280 | 0.5625 | 上下各裁 9.4% | +1.87MB |

- 区域实测 = `Scene_BG` = **582.39 × 840**（和 `GameLayer` 同框），比例 **0.6933**。
- **选 3:4 不选 9:16 的理由**：视频元素是按 **CSS 像素**铺的（拼图区在手机上约 318 CSS px 宽），
  480 宽的片源其实是**缩小显示**、不会发虚 ⇒ 9:16 的高分辨率优势用不上，却要多裁 9.4%（内容损失）+ 多背 0.8MB。
  只有横屏（`GameLayer` ×1.4）时 9:16 才有清晰度优势。
- 想一点都不裁就让美术按 **0.6933**（≈ 582:840）出。

**体积账**（`npm run pack:report` 现跑）：当前载荷 **1.92MB**，容器 = gzip(9) → base85（**×1.25**），
门禁 `LIMIT = 5MiB` 且 `throwError = true`。0.84MB 的片源 ⇒ 加完约 **3.0MB**，余量约 2MB。
⚠️ mp4 已经压过、gzip 收不动它，**这 1.25 倍是躲不掉的**；换片先按「片源 × 1.25 + 现载荷 < 5MB」估。

**顺带补的**：`tools/js/verify-scene.js` 加了一条 `checkEndVideo`（配了视频才查）—— 节点必须睡着、不能挂 Widget、
`player` / `clip` / `region` 都得配。`tools/js/mount-end-video.js` 是幂等接线脚本。

**还没验的**（同上 §18「还没验的」那四条，重点是前两条要真机 / 真容器）：
① 有声自动播放到底放不放行；② `CLICKED` 跳过在容器里灵不灵；③ Safari 那两条 blob 修复（**只能在单文件产物里验**）；
④ `video` 模块重开之后**引擎必须重编**（去「设置 → 功能裁剪」保存一次），体积也要等下一次 release 构建才给准数。

## 收尾改版：去掉那道横扫的扫光，画笔时长 2.5s → 1.5s（2026-10-15）

**改了三处**（都在 `tools/js/set-finale.js` 成对写的那几个数里）：

- `FeatureFlags.sweepOnComplete` → **false**：最后一格露面后不再定格 0.5s、也没有那 0.9s 的横扫光；
- `SceneBgSwap.delay` → **0**：最后一格露面**当刻落笔**（扫光关着时它必须是 0，`verify-scene.js` 的
  `checkFinale` 专盯这条「白等」）；
- `SceneBgSwap.revealTime` → **1.5s**（原 2.5s）：画笔刷完更快，演完就抛 `END_SHOW`。

`RepairSweep.completeDelay / completeTime` 那两个数（0.5 / 0.9）**留在组件上没动** —— handler 首行就被开关
gate 掉了，整段不演；留着是万一要开回来。

**现在的时间轴**：最后一格露面 → 0.0 落笔 → **1.5s** 刷完 → `END_SHOW` → 结尾视频 3.88s（见下一条）
→ 结束界面。从最后一格露面到出 CTA 约 **5.4s**（之前是 3.9 + 3.88 ≈ 7.8s）。

**怎么改的**：`set-finale.js` 改成带开关的形式 —— **不传 args 就是现在这个「扫光关着」的状态**，
想开回来跑 `node tools/exec.mjs scene tools/js/set-finale.js "{\"sweep\":true}"`。
`revealTime` 是手调值，`set-scene-brush.js` 只在它 ≤1.3 时才抬到 2.5，所以 1.5 不会被脚本悄悄改回去。

**还没验的**：只跑了 `verify-scene.js`（收尾那对数和视频那几条都没报）。**观感没验** ——
1.5s 的笔刷是不是太急、去掉定格之后会不会显得「一露脸就刷」，得在 Game View / 真机上看。

## 收尾再改：完成图「直接亮出来」，画笔涂色也撤了（2026-10-15）

**要什么**：最后一格放好之后**直接把完成背景亮出来**，不要任何花哨效果，然后进结尾视频。

**怎么做的**：`SceneBgSwap` 加了一个 `instant` 开关（**默认勾着**），走「当刻收尾」那条：把 `完成背景` 的贴图
挪到 `Scene_BG` 上、把 `完成背景` 睡回去、立刻抛 `END_SHOW` —— **不建材质、不起 tween、不撒仙尘**。
画笔那一整套（材质 / `revealTime` / `rows` / `radius` / `feather`）原样留在组件上，取消勾选 `instant` 就退回它。
**两条路的收尾状态一模一样**（贴图在 `Scene_BG` 上、两个子节点都睡着），所以下游（结尾视频 / 结束界面）
不用知道走的是哪条 —— 这是这次改造刻意守住的一点。

顺带把 `reveal()` 里原来那条「没配画笔材质就直接抛 `END_SHOW`」的兜底也改成**先收尾再抛**：
以前那样万一材质配漏了，完成图根本不会出现，玩家看到的还是线稿，而且没有任何报错。

**现在整条收尾**：最后一格露面 → **当刻亮完成图** → `END_SHOW` → 结尾视频 3.88s（§18）→ 结束界面。
从最后一格露面到出 CTA 约 **3.9s**（只剩视频那一段）。

**怎么落地的**：`SceneBgSwap.instant` 默认 `true`（新场景 / 新实例也是这个），场景里由
`tools/js/mount-scene-bg.js` 显式写一遍；`revealView` / `brushEffect` / `dust` 三个接线照旧。
`tools/js/set-scene-brush.js` 里写明「`instant` 勾着时这几个数都不起作用」，
`set-finale.js` 的 `toEndShow` 也按 `instant` 分了两条算法。

**没验的**：`verify-scene.js` 过（新加的一条「`instant` 勾着却没配 `revealView`」也没报）；
**观感没验** —— 「完成图一亮就进视频」这一下衔接硬不硬、要不要留半拍，得看 Game View / 真机。

**还挂着的一个小问题**：`AudioManager` 的 `LAST_SHOWN` 那条 cue（`魔法光粒.MP3`）本来是配给「画笔开演」的，
画笔不演了它照旧在最后一格露面时响，而 `END_SHOW` 紧接着 `stopAll()` —— 听感是一声被掐掉的短音。
删还是留，等定（见 AGENTS.md「待确认」第 5 条）。

### 再改：亮图提前到「最后一块落位当刻」，视频留到放置演完（2026-10-15）

**要什么**：「激活完成背景可以提前到最后一组物品放置时，然后放置完成后再播视频。」

**怎么落的**：**没加事件、没改发射方** —— 两拍都借现成的：

| 拍 | 借谁 | 为什么它就是那一拍 |
|---|---|---|
| ① 亮完成图 | `LEVEL_COMPLETE` | `RepairSystem.onSnap` 里**计数到齐**那一刻抛的（`_done < _data.length` 就 return，所以只可能在**最后一块吸附成功**那一下）—— 此刻所有碎片**都已落位**，还在演的只有最后那几格的「贴纸按平」 |
| ② 抛 `END_SHOW` | 最后一个 `PIECE_SHOWN` | `PieceSlot.spotDone()` 抛的，是「这一格的揭晓（贴纸按平 / 收尾动作）演完」= **放置那一段完成** |

`SceneBgSwap` 因此**多听一个 `LEVEL_COMPLETE`**（只在监听侧加，§5 允许）：`instant` 模式在这一拍亮图、
在最后一个 `PIECE_SHOWN` 抛 `END_SHOW`；画笔模式（`instant = false`）**不提前** —— 照旧等最后一格露面才落笔。

**结构**：把 `reveal()` 拆成「`reveal()` 只负责亮（`_revealed` 守）」+「`endShow()` 只负责抛（`_ended` 守）」，
画笔的 `finish()` 与 `onShown()` 都收口到 `endShow()`。另加一条兜底：最后一格露面时**先补亮图再抛事件** ——
万一 `LEVEL_COMPLETE` 没来 / 来晚了，也不会把线稿带去结束界面。

**⚠️ 有意改掉的一条老约定**：`PieceSlot.shown()` 的注释里写着「完成背景按 `PIECE_SHOWN` 计数，这一格要是
最后一块修好的，动作还没演完完成背景就盖上来，整段表现被吞掉」—— 这次就是**主动**要它盖上来（亮图提前）。
代价是最后那几格的「贴纸按平」会演在**已经完整**的画面上；因为那块碎片本来就是这幅图的一部分，
看上去是「碎片按平到图上」，不会有缺口。

**没验的**：`verify-scene.js` 过（收尾 / 视频相关一条不报）；观感没验 —— 这一下硬不硬、
要不要在亮图与视频之间留半拍，得看 Game View / 真机。
